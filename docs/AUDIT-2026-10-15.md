# GalleryEdge v1.0.0 深度审计（2026-10-15）

基线：`main@a720672`。修复分支：`fix/audit-hardening-20261015`，PR #28。本次以静态源代码核查、回归测试与 GitHub Actions 为依据，**不等同于真实生产系统渗透测试**。

## 已定位并提交修复

|---|---|---|---|
| 高 | 安装向导只检查客户端地址、缺少 Host/Origin 和写请求特殊 Header 防护，存在 DNS rebinding/跨站驱动风险 | `galleryedge_panel/cli.py` | 实际向导中间件拒绝伪造 Host/跨域/缺失请求头 |

| 中 | 重启后挂起的 `running` 任务不会再次被领取 | `galleryedge_ops/jobs.py` | 启动标记“中断”，手动确认后重试 |
| 中高 | 邀请码检查与标记使用分离，多个并发注册可能重复消费 | `galleryedge_ops/auth.py` | 条件 UPDATE RETURNING 原子认领邀请码 |
| 中 | 未知用户名使用更低成本的 scrypt 验证，存在时间侧信道 | `galleryedge_ops/auth.py` | 统一使用固定成本的虚拟哈希验证 |

## 未处理 / 需要专门验收

1. **跨库备份闭环**：`ge-db-backup` 默认仅覆盖 `works` / `work_tags` / `meta`，没有单独备份独立 usage DB（API keys、计划、日/月统计）；运维面板需提供独立备份与一致性恢复说明。
2. **多进程任务持久化**：本次将遗留运行任务标记为中断；尚未实现租约、心跳、取消、重试幂等性与多进程一致领任务。
3. **数据库恢复运行中异常**：预校验修复了损坏备份污染空库问题；恢复期间遇到网络或数据库写入异常仍可能留下部分数据。应使用 staging DB + 完整校验后切换。
4. **SQLite 线程模型**：panel 默认 `check_same_thread=False` 并在 web handler、后台 runner 和 sampler 中复用连接；建议分离连接/事务作用域并压力测试。
5. **安装包完整性**：无 Node.js 且发行包未包含 `web/dist` 时，首次安装可能完成但没有前端界面。应在发行工艺中提供预构建静态资源。
6. **加密保险库威胁模型**：向导为方便使用，会在本机 0600 文件保存 vault 口令。建议提供不落盘的解锁模式，文档讲清楚 0600 与加密静态凭据的安全取舍。
7. **大数据检索**：API `COUNT(*) + OFFSET` 深分页、频繁标签聚合，Turso 多用户/千万级下需压测并考虑游标分页及缓存。
8. **真实端到端集成**：S3/R2 以兼容模拟器为主；Cloudflare 发布使用假客户端；需要隔离的真实 R2/Turso/Workers staging 冒烟及故障回滚测试。
9. **索引快照一致性**：大规模 dump 分批扫描期间若有并发写入，尚无跨多个 Hrana 请求的读快照保障，需写入暂停或数据库原生快照。
10. **运维文档同步**：`WHITEPAPER.md` 的旧阶段限制与最新 Cloudflare 版本发布功能部分不一致，需统一。

## 第二轮：文件系统、WebDAV、归档处理

- **WebDAV 认证重定向（高）**：Python `urllib.request` 默认处理 3xx 重定向会复制请求的 `Authorization` header。对于凭据由 Vault 提供的 WebDAV Basic Auth，这可能把认证发送到外部重定向域。修复：默认 opener 拒绝重定向，配置时直接填最终端点；添加双本地 HTTP 服务验证不转发凭据。
- **本地后端软链接路径逃逸（高）**：只拦截 `../` 不足以防止既存符号链接指向存储目录外。修复：读写、删除、head 均检查解析后路径在存储根目录内；列举与用量统计排除符号链接。未覆盖攻击者并发替换目录的 TOCTOU 场景；如需暴露给不可信本地用户，须进一步采用 `openat` / `O_NOFOLLOW`。
- **回滚版本路径（中）**：版本切换和回滚统一执行严格版本格式检查，避免通过 `to` 直接注入文件路径。
- **TAR 重复项和内存使用（中高）**：导入前拒绝重复文件名、异常成员与超大元数据。入库在逐块校验媒体内容和哈希时不再把图片内容全部加载到 Python 进程内；外部调用 `read_pack()` 默认仍返回媒体字节以维持兼容。

- **HTTP 错误响应无界读取（中）**：`HttpFetcher` 对 2xx 响应最多读取 5MB，但处理 `urllib.error.HTTPError` 时使用不带大小上限的 `e.read()`，恶意来源可使用超大错误响应消耗内存。修复为成功/错误响应统一读取 5MB+1，超过上限明确标记为 `response-too-large`，防止静默截断损坏素材；新增回归测试。

- **首次安装中的密钥扩散（中）**：`setup.apply()` 曾将新 Vault 口令写入进程级环境变量，随后执行 `npm ci` / `npm run build`，任何依赖安装脚本可读取此环境变量。修复为 Vault 初始化显式传入口令、不污染进程环境，并为 npm 子进程过滤 `GE_VAULT_PASSPHRASE`。注意这不能防止同一系统用户下的恶意本地程序读取安装向导保存的口令文件；若需要抵抗不可信本机代码，仍要设计不落盘口令及前端预构建发布模式。

- **作品数字字段原样拼接 HTML（高）**：Python 参考站与 TS Worker 的列表页直接插入 `image_count`。SQLite 的 `INTEGER` 是亲和类型而非严格校验，非数字文本可留在字段中形成存储型 XSS。修复：两个渲染端统一 HTML 转义、入库验证 `image_count` 必须为限定范围内整数，并对 Python 作品页的外部来源链接采用 HTTP(S) 白名单。测试向非严格 SQLite 字段注入标签，验证不会形成实际 HTML 元素。

- **管理面板不可信源链接（中）**：React 的只读内容页此前直接把作品 `source_url` 写入外链、把 `cover_url` 写入图片地址；数据被错误导入或篡改时会允许非 HTTP(S) scheme。改为合法 HTTP(S) 才生成链接和图片，其他数据只显示文字；增加前端测试。
